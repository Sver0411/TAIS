## 上传优化的独立价值

- **SU20对JO-S**：全部采样时间、间隔、scores、候选、active及C11输出一致，TP622、Precision40.68%、Recall69.11%、F151.21%完全相同。上传52,938→29,970，**−43.39%**；字节1,860,232→1,051,571，**−43.47%**，差−808,661，种子簇95%CI[−818,740.2,−798,355.725]字节。共同检出的622个事件报告时间差0，95%CI[0,0]。
- **Gate+U对Gate**：采样75,428、TP434、P/R/F1、故障诱发439全部不变；上传47,549→26,371（−44.54%），字节1,673,222→927,272（**−44.58%**），差95%CI[−750,668.5,−741,215.85]。434个共同事件报告时间差0。它没有提高算法检出能力，但不能为突出SU而删掉这个简单竞争选项。
- 接收端实际匹配TP：JO-S **621**、SU20 **622**；其余方法与表中TP一致。差异为seed586 `stable_offset_same_long`：原S在660s本地清除active却不上传，675s再次上传active=True，接收端仍以为同一事件持续；SU在660s上传False，675s收到新边沿。675s报告匹配676s真值起点遵循原±5s容差，不是预测真值或修改规则。[实际上下文](../results/tais-su/test/receiver-edge-difference.json)。旧S接收端P/R/F1为40.6414%/69.0000%/51.1532%，不能把其本地622冒充接收621之外的已知信息。
- 所有U版本在本轮每个实际采样事件/原始C11状态或flags边沿均当次发送，重要边沿未上报0、最大采样后上传延迟0。原Gate最大边沿延迟55s；原S还存在一次未收到的清除边沿。上述即时性只指**已经采样的变化、理想字节链路**，不代表物理发生后零延迟或可靠无线交付。
- 每帧保留完整测量、健康score/state/flags、事件及时间，原v1无损解码；**整个时间序列并非无损传输**，U抑制了小幅数值更新，必须同时检查年龄、重构和覆盖。

## 推荐与实际运行

**均衡替代NO-GO，Core默认仍GateOnly。** 预选30秒质量比Gate提高，但只保留56.38%S召回增益、采样高于TrustLog13.96%、诱发误报增加7.06%，未通过80%增益保留、采样附近(+10%)和误报(+5%及区间)门槛。40秒的成本确实更好，然而也损失86个事件、只保留54.26%增益且误报增加；不能根据最终结果重新选择它为已验证默认。保留其真实操作点，允许按已知代价做工程选择，不称三目标同时达成。

高检出SU20适用于愿意承担151,448次采样（比Gate增加100.78%）的实验模式；其质量显著高于Gate且字节更低。Gate+U保留当前检测与采样、更少上传，适合作为独立通信选项，但普通数据更旧；没有因此自动改默认。距离原目标仍缺：高Recall与接近TrustLog的采样同时成立、故障诱发误报不增加，以及实际部署/自然故障/电能证据。停止本轮调参，不加H或新分类规则。

```sh
# 项目根目录，输出必须新路径；默认不传--policy仍GateOnly。
.venv/bin/python examples/tais-core/run.py --policy tais-su --su-mode high \
  --scenario clean_short --seed 20 --pace .01 --ui live --verify \
  --out results/scratch/su-high-new-01
.venv/bin/python examples/tais-core/run.py --policy tais-su --su-mode balanced \
  --scenario drift_same_long --seed 20 --pace .01 --ui live --verify \
  --out results/scratch/su-balanced-new-01
# 简单通信竞争方案
.venv/bin/python examples/tais-core/run.py --policy gateonly-u \
  --scenario missing_cross_long --seed 20 --pace 0 --ui log --verify \
  --out results/scratch/gate-u-new-01
```

“balanced”只是预先选定的30秒候选，不是通过门槛的背书。40秒已有冻结benchmark和`SUSender(cfg,cap=40)`接口，不增加测试后择优参数。用户CSV/逐条JSONL仍支持，没有独立真值时指标N/A。

六类场景各运行高/均衡两种模式，另有Gate+U跨通道和完全遮蔽失败演示，共14个实际Core流；[真实收发JSONL/终端记录](../results/tais-su/core/)。例如旧seed20干净短事件两种模式都检出1/1，但另有1个未匹配；高模式105采样/21上传/754字节，30秒83采样/22上传/791字节，较少采样不保证每个案例字节更低。温度缺失+湿度事件，高模式124/22/702字节，30秒101/20/639字节，均检出1/1且保留1个未匹配。漂移无事件两种模式仍2个错误报告，未隐藏。

全套软件实际 **802 passed, 2原有严格xfail, 0failed**，新增102项；旧Core/JO策略测试未改。旧种子全45场景的本地候选、原C11、采样、实际接收、边沿及三个cap的一致性测试均运行。最终完整记录、counterfactual和真实帧均落盘，独立核验重新计算匹配、诱发计数、接收边沿、字节、pooled年龄及上传层本地输出一致性，不重跑或选择策略。[核验](../results/tais-su/checks/archive-verification.json)。所有既有普通文件除Core可选入口外逐字节核验，两个子模块及五个C0原文件保持不变。
